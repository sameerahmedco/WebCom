# WebCom Support

## Bugs and feature requests

Use the repository's GitHub issue templates for reproducible browser bugs and feature requests. For a bug, include the WebCom version, Windows version/architecture, WebView2 Runtime version, whether a clean profile reproduces it, and the smallest safe reproduction steps.

Do not attach passwords, cookie values, authentication tokens, private browsing data, or other secrets. The native **Report a Problem** page can prepare a privacy-safe template and local diagnostic/recovery bundles for review before sharing.

## Build failures

Attach `build-last.log` or quote the first meaningful compiler/linker error block. State whether the build came from a fresh extraction and whether any diagnostic-only switches such as `-AllowCompilerWarnings` were used.

## Security issues

Do not use a normal public issue for vulnerabilities. Follow `SECURITY.md` and use the repository's private vulnerability-reporting/security-advisory path when available.

## Privacy questions

See `PRIVACY.md` for what WebCom itself stores or uploads and for the separate Microsoft Edge WebView2 / website privacy boundary.
